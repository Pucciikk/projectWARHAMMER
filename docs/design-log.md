## Правила работы с кодом

1. **API Minecraft/NeoForge меняется между версиями.** Если не уверен в точной сигнатуре или имени класса для 1.21.1 — прямо скажи об этом и предложи, где проверить (исходники в IDE, документация NeoForge). Не выдумывай API уверенным тоном.
2. Давай **полные файлы с путями** (`src/main/java/...`, `src/main/resources/...`), а не обрывки, если изменение не совсем точечное.
3. Работаем **маленькими шагами**: каждый шаг компилируется и проверяется в игре.
4. **Сначала каркас, потом контент.** Если для нового оружия/брони/моба нужно писать новый класс — значит, каркас недоделан.
5. **Цифры в данных, а не в коде**: характеристики оружия, брони, мобов, модулей кораблей — в JSON (datapack / data maps / конфиги), чтобы баланс правился без перекомпиляции.
6. **Датаген с самого начала**: модели предметов, локализация, рецепты, лут, теги.
7. Всегда учитывай разделение **клиент / сервер** и синхронизацию. Всё, что отображается, интерполируется по `partialTick`.

## Главный принцип качества: никакой «топорности»

Это ключевое требование проекта. Большинство модов (особенно сделанных наспех) выглядят плохо из-за дешёвых механик моделей. Мы так не делаем:

- **Хитбокс соответствует модели.** Модель не должна торчать за хитбокс и проваливаться в блоки.
- **Вес и инерция** у техники: плавный разгон и торможение, ограниченная скорость поворота, раздельный поворот торса и ног у шагающих машин, никаких прыжков у тяжёлой техники (только подъём на блок), тяжёлое приземление.
- **Движение привязано к анимации** (шаги синхронизированы со скоростью — никакого скольжения ног).
- **Никаких рывков**: техникой управляет клиент водителя, сервер проверяет; собственные величины интерполируются; состояние синхронизируется через `SynchedEntityData`.
- Ощущения передаются через камеру, звук и частицы: покачивание в такт шагам, тряска, гул сервоприводов.
- Позже — IK ног (подстройка под рельеф) и реакция рук на стены.
- Никакой техники «как лошадь, на которую натянули модель».

### Ядро геймплея: путешествия через варп на кораблях

**Верфь** — мультиблочная постройка. Корабль собирается в ней из **корпуса** и **модулей**.

- **Корпус** определяет класс корабля (фрегат → лёгкий крейсер → крейсер и т.д.) и количество слотов. Класс доступного корпуса зависит от размера/уровня верфи.
- **Обязательные модули**: реактор, варп-двигатель, генератор Поля Геллера, навигационный модуль (требует Навигатора — NPC).
- **Дополнительные модули**: пустотные щиты, лэнс-батареи, ангар, казармы, часовня (снижает порчу), апотекарион / генная лаборатория, мануфакторум, телепортариум и т.д.
- Сборка: модули ставятся в GUI верфи → «заложить киль» → постройка идёт **со временем** и потребляет ресурсы; в доке визуально растёт корпус (модель/строительные леса).
- Корабль — это **данные** (корпус + модули + состояние), а не постройка из блоков. В доке снаружи он показывается моделью.

**Интерьер корабля — отдельное измерение.**

- Одно «корабельное» измерение, каждому кораблю выделяется свой участок (как в Compact Machines).
- Интерьер генерируется из шаблонов: корпус задаёт «хребет» (главный коридор, мостик), **каждый установленный модуль добавляет свой отсек** (поставил часовню — на корабле появилась часовня).
- Есть «управляемые» отсеки (перестраиваются при смене модулей) и «личные» зоны игрока (каюты, ангар), которые сохраняются.
- Корабль населён NPC (сервиторы, экипаж, матросы), чтобы ощущался живым.
- Вход: трап/телепорт у верфи, шаттл, телепортариум.

**Варп-переход.**

- На мостике — навигационный стол: выбор пункта назначения.
- Переход занимает время. Качество Навигатора и модулей влияет на длительность и риск.
- Во время перехода — **варп-события**: сбои Поля Геллера, прорывы демонов **внутрь корабля**, порча экипажа.
- **Визуал за шлюзами и иллюминаторами**: собственный рендер неба измерения (`DimensionSpecialEffects` + свой sky renderer/шейдер): кружащийся варп, красные молнии, тени демонов, давящих на Поле Геллера. Ощущение движения: параллакс и скорость прокрутки слоёв, лёгкая тряска, скрип корпуса, мерцание света.
- Измерение корабля неподвижно — всё «движение» делается рендером. Небо зависит от состояния корабля, в котором находится игрок (на орбите — планета под кораблём, в варпе — варп).
- По прибытии — высадка на планету (телепортариум / шаттл / посадочный маяк).

### Генная инженерия (прогрессия игрока)

Игрок превращает себя по стадиям, в генной лаборатории / апотекарионе:

- **Человек → Громовой Воин → Астартес → Примарис**.
- Громовой Воин — сильный, но нестабильный путь (деградация/шкала нестабильности) — интересный компромисс.
- Каждая стадия: импланты (упрощённо, ключевые органы, каждый даёт перк), риск отторжения, рост (атрибут `SCALE`), доступ к новому снаряжению.
- **Терминатор** по лору — не генетика, а доспех и ранг ветерана: тактический дредноут-доспех требует импланта Чёрного Панциря и ранга.
- **Дредноут** — возможно, через погребение павшего Астартес в саркофаге (обсудить).

## Фундаментальные системы (делаются первыми)

1. **Данные игрока** (NeoForge Data Attachments + синхронизация): фракция, ранг, стадия генной модификации, порча, благосклонность богов.
2. **Матрица фракций** (данными): кто кому враг.
3. **Оружейный каркас**: один движок дальнобойного оружия, конкретное оружие — набор параметров в JSON. Свои типы урона и бронепробитие. Каркас ближнего боя.
4. **Бронекаркас**: флак, карапас, силовая броня, броня Хаоса; бонусы комплекта; требования (импланты).
5. **Каркас солдата-моба**: общий гуманоид с дальнобойным AI, цели из матрицы фракций.
6. **Корабельный каркас**: данные корабля, измерение интерьеров с выделением участков, телепортация внутрь/наружу, состояние (орбита / варп / пункт назначения).

## Структуры, данжи, измерения — как делаем

- **Jigsaw** из модулей + **процессоры структур** (автоматическое разрушение, замена на треснутые блоки, мусор, мох). Руины прощают кривое строительство и атмосфернее.
- Повторяющаяся архитектура — **генераторы `.nbt` на Python** (`nbtlib`, `mcschematic`).
- Крупные уникальные объекты — конвертация 3D-моделей (ObjToSchematic).
- Модули строятся с WorldEdit / Axiom.
- Измерения — JSON ворлдгена (генераторы misode.github.io) + свой код там, где нужно (лабиринт Тзинча, небо).

## Модели и текстуры

- Все модели — качественные 3D (GeckoLib + Blockbench), с продуманными анимациями.
- Текстуры: генерируются процедурно на Python (металл, керамит, ржавчина, панели, заклёпки, руды, иконки предметов), игрок дорабатывает.
